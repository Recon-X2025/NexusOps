## 1 · Employee form — the one path that fully worked

**Positive (persisted, read back).** Anita Rao created via HR → Add employee, assigned COH-02-struct, state Karnataka, PAN `ABCDE1234F`, start 2026-07-15. DB read-back:
`state=Karnataka · regime=new · pan=v2:…(encrypted) · structure=linked · start=2026-07-15 · status=active`.
→ All statutory fields persisted; **PAN is stored encrypted at rest** (`v2:` envelope — the PAN-encryption work is firing on form input).

**Corrected claim (traced, isolated the trigger).** Stage Three tentatively noted the form "omits state/regime/PAN". That was a partial-render artefact, now resolved: **the statutory section (State, Tax regime, PAN, UAN/ESI/bank) renders only after a salary structure is selected**, and once it does, **State is required** and Create is disabled until it's set. The regime field is labelled "locked 12 months". So the form does **not** silently omit statutory fields for a payroll-linked employee — it **requires** state and exposes regime/PAN. This is the opposite of a gap.

**Negatives (from Stage Three, still valid):** empty submit refused; malformed email + future date refused (native browser validation) — in both cases with **no app-level message**. I did **not** re-run the malformed-PAN-persist negative this pass (budget).

## 3 · Bulk importer — documented, not executable via this harness

Import CSV opens a 5-step wizard whose Step 1 requires a **CSV file** (drag-drop or browse → native picker). **This browser surface cannot supply a file**, so no import ran — happy path and all importer negatives (missing column, blank required cell, unknown structure name, duplicate) are **unrun**. What I did capture:

- **Required columns:** `name, email, structureName, state, taxRegime` (starred). Optional: department, title, jobGrade, employmentType, location, city, isMetroCity, startDate, pan, uan, esiIpNumber, bank*, gender, dateOfBirth.
- **Guards (from `ingest.ts`, read not run):** the file is **refused whole if the `taxRegime` column is absent** ("Nothing was imported") — a deliberate guard so a missing header can't silently elect the new regime for everyone; **salary structures matched by name** (unknown/ambiguous skipped and reported); **duplicate emails become named skips** (not a batch abort); **PAN stored encrypted**. These read as good, defensive behaviours — but they are **code-verified, not runtime-verified** this pass.

## 4 · The 429, revisited

This supports the Stage Three lean that the earlier storm was **request-volume-driven (harness) against a dev bucket**, not a hard product defect — while the *user-facing* lesson stands: a 429 (whatever the cause) surfaces as a silently-failed form.
