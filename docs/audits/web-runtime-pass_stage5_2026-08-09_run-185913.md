## 1 · The complete fix (all four gates + server), and how each was found

The payroll surface gated the approver out at **four** layers; the static diagnosis (run-173221) named two, and live testing this stage found the other two:

| Layer | Gate (before) | Fix | Found by |
|---|---|---|---|
| Server: `runs.list`/`runs.get` | `permissionProcedure("payroll","read")` | `anyPermissionProcedure([["payroll","read"],["financial","write"]])` | static |
| Client: route guard | `canAccess("payroll")` | `resolveRouteReadAlternatives` → also admit `financial.write` | static |
| Client: page inline view gate | `if (!can("payroll","read")) return AccessDenied` | `payroll.read || financial.write`, **relocated after all hooks** (my change surfaced a latent rules-of-hooks crash) | **live (Stage Four/Five)** |
| Client: per-step Execute button | single `can("hr","write")` for every step | Finance/CFO steps → `can("financial","write")`; others unchanged | **live (Stage Four)** |
| Client: query-enable (`mergeTrpcQueryOpts`) | generated map `payroll.runs.list` → `{payroll,read}` | teach generator about `anyPermissionProcedure` → regenerate → `{protected}` | **live (this stage)** |

Files changed (uncommitted): `apps/api/src/lib/trpc.ts`, `apps/api/src/routers/payroll.ts`, `apps/web/src/lib/route-permissions.ts`, `apps/web/src/components/layout/route-guard.tsx`, `apps/web/src/app/app/payroll/page.tsx`, `scripts/generate-trpc-rbac-map.ts`, `apps/web/src/lib/trpc-procedure-rbac.generated.ts` (regenerated: `runs.list`/`get` → protected, plus two drift entries the stale map was missing — `financial.createCreditDebitNote`, `ingest.importEmployees`), and new test `apps/api/src/__tests__/payroll-approval-gate.test.ts`. **The approve action's permissions, the SoD check, and the RBAC matrix are untouched.**
