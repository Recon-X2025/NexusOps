## 1 · Meera Menon (60% structure — the marquee >50% case): NO PAYSLIP

**Meera produced zero payslips.** Traced to cause before recording: her structure "Senior Band L6 basic60" has **`effective_from = 2026-08-09`**, which postdates the August period start (2026-08-01). The resolver found no structure version effective for the period and **silently excluded her** — she was counted in the "12 employees" at period-lock, then dropped to 11 by payslip generation, with **no error naming her** (the Errors list flagged only the two ESI members).

Consequence: **the >50% wage-base clamp still has not run against a real employee** — the one employee who could exercise it was dropped. The immediate cause is my own input (I left the structure's effective-date at today's default), so this is not itself a computation defect. **The product finding is the silence:** an employee who is selected into a run but whose structure isn't yet effective is removed with no warning and a bare headcount change — a customer would not know their highest-paid employee wasn't paid. To obtain Meera's numbers, the structure needs an earlier effective date or a September+ run (not executed — budget).
